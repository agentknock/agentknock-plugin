# Contributing to the Agentknock plugin

Contributions take the form of GitHub issues: bug reports, feature proposals,
and design discussions. The maintainers write the final changes that result
from those issues.

## Open an issue

Before opening an issue, search for an existing discussion. Use the bug report
form for incorrect behavior and the feature proposal form for changes or
additions to the skill, plugins, or marketplaces.

Describe the problem and its effect. A preliminary design is welcome but not
required. Opening an issue starts a discussion; it doesn't guarantee a change.
The maintainers make the final scope and design decisions.

Treat issues and pull requests as public. Don't include secret values, pairing
data, authentication tokens, or other sensitive information.

If an issue results in a change, the maintainers credit its author by GitHub
username in the resulting commit.

## Pull requests

A proposed edit or reproduction can help explain an issue. After an issue
exists, you're welcome to open a pull request that demonstrates the idea or
problem. Link the pull request to the issue and keep the design discussion in
the issue.

The maintainers treat the pull request as supporting material rather than a
change to merge. If the issue results in a change, the maintainers implement
it independently and close the pull request without merging it. A pull request
needs a linked issue so that the discussion remains in one place. Without one,
the maintainers close the pull request and ask for an issue instead.

## Report a vulnerability

Follow the private reporting instructions in [SECURITY.md](SECURITY.md).
